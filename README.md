# PageVoice

A local-first PDF/EPUB → audiobook application, implemented from scratch.

## Development plan

The CLI phases were reviewed individually. The remaining phases are authorized
for completion; finished branches are reviewed through PRs and merged:

1. EPUB → chaptered M4B CLI, engine registry, local smoke test.
2. PDF + OCR, crash recovery, sentence regeneration.
3. FastAPI upload, queue, progress (SSE), download.
4. React/Vite/Tailwind accessible reader UI, previews and consent-based voice cloning.
5. Character detection and voice casting.
6. Optional engines and an OpenAI-compatible speech endpoint.

`main` starts with this README only. Four feature branches cover the project:
`feat/pipeline` (1–2), `feat/api` (3), `feat/reader-ui` (4), and
`feat/voices-engines` (5–6). Maximum four commits per feature branch;
reviewed changes land through pull requests later. Do not create extra branches.

## Architecture

Parse → clean → chapters → sentences → optional speakers → audio chunks → FFmpeg.
Python CLI first, then FastAPI and React. Local `uploads/`, `voices/`,
`outputs/`, `sessions/`; no accounts. XTTSv2 via maintained `coqui-tts`
is the default engine; Edge is an optional online draft engine. Voice cloning
requires the speaker's consent. Model downloads require initial internet access.

## Implementation policy

Reference READMEs are inspiration only; no reference implementation is copied,
cloned, vendored, or wrapped. Standard PyPI/npm dependencies are allowed.
Design guidance will be read before phase 4. Every claimed working feature
must have a recorded verification run.

### One-command setup

Prerequisites: Python 3.10–3.13 and FFmpeg/ffprobe on PATH. This machine was
verified with Python **3.10.12**, FFmpeg **8.1**, macOS arm64. Node **22.13.1**
is installed but not used until phase 4. On macOS, install FFmpeg with
`brew install ffmpeg` if missing. Scanned PDFs also need Tesseract
(`brew install tesseract` on macOS). Then run:

```sh
./scripts/setup.sh
```

The script creates `.venv` and installs pinned core/test dependencies using
`requirements-core.lock`. Override the Python executable with `PYTHON=python3.11`.
No model, cloud service, account, or API key is required for the macOS draft path.
Setup needs internet for PyPI; subsequent `say` conversions run offline with
an installed macOS voice.

```sh
.venv/bin/python tests/sample.py outputs/sample.epub
.venv/bin/pagevoice inspect outputs/sample.epub
.venv/bin/pagevoice convert outputs/sample.epub --engine say
.venv/bin/pytest -q
```

Use `--format mp3` for MP3; M4B is the default. `--voice Samantha` selects an
installed macOS voice (`say -v '?'` lists voices). `--language es` selects Spanish (Monica for macOS, Elvira for Edge); `en`
selects English. All other language codes are rejected. This overrides EPUB
language. `--data-dir /path/to/library` sets the storage root. The CLI prints
the session and output paths. Book title, author, language, and chapter titles
are included in the output. MP3 chapter display depends on your player.

### PDF, resume, and sentence editing

```sh
.venv/bin/pagevoice inspect book.pdf --ocr auto
.venv/bin/pagevoice convert book.pdf --engine say
# Replace <id> with the session ID printed by convert.
.venv/bin/pagevoice resume sessions/<id>
.venv/bin/pagevoice sentences sessions/<id>
.venv/bin/pagevoice regen sessions/<id> 0000-00001 --text "The lantern shone across the water."
```

PDFs use embedded text when available; `--ocr auto` runs local Tesseract on pages
with fewer than 24 alphanumeric characters. `--ocr always` renders every page
for OCR, and `--ocr never` refuses textless pages. `--language` sets narration and
sentence splitting; `--ocr-language eng+spa` independently selects installed
Tesseract data (`tesseract --list-langs`). The default OCR language follows the
book language; PDFs without a language tag default to English. Missing OCR tools
or language packs produce actionable errors. No PDF content leaves the machine.
PDFium renders OCR input; Poppler is only needed to render test fixtures for visual QA.

PDF top-level bookmarks define chapter starts at page boundaries. Without
bookmarks, English or Spanish chapter headings in the first three
nonempty lines start chapters. Otherwise pages become chapters; pages following
a detected chapter heading remain in that chapter until the next heading.
Nested bookmarks and intra-page destinations are not resolved. The inspection
JSON includes per-page native/OCR provenance and warnings for pages with no
recognized text. Review these warnings: blank pages and failed recognition can
look alike. Encrypted PDFs are rejected.

`resume` accepts a **session directory**, not a source book. It checks WAV validity,
text/settings fingerprints, and SHA-256 before reusing chunks. Missing, damaged,
or stale chunks are synthesized again, then the final audio is rebuilt. Re-running
`convert` deliberately creates a new session. PDF parsing also resumes from cached
pages. If parsing was interrupted, the stored upload must still match its checksum.
Phase 1 sessions are upgraded in place on resume; their existing audio is validated
and given checksums. Keep the full storage root together if moving it.

Sentence IDs use zero-based `chapter-sentence` indexes. `regen` keeps the ID and
replaces only that sentence's audio; omit `--text` for a new take with unchanged
text. Replacement text is limited to 220 characters so it remains one bounded
chunk. A regeneration request is saved before synthesis: if interrupted, `resume`
finishes that request. Existing output is retained until a replacement export is
ready; `output_current: false` in the manifest means it predates pending work.
On an incomplete session, regeneration also finishes any other missing chunks.

An OS-backed session lock prevents concurrent writers and releases automatically
when a process exits or is killed. A hard kill can leave the last status as
`synthesizing`; `resume` uses the lock and chunk checks rather than trusting that
status. Do not manually delete a lock while a writer is running. Orphaned/previous
audio generations are retained to avoid destructive cleanup; they consume disk
space but are never selected just because they exist. Successful runs report
exact reused/synthesized counts. Resume always re-encodes the final audiobook;
it does not require the TTS engine if all chunks are valid. Edge opt-in is required
again for any resumed/regenerated chunks sent online.

Create the original test PDFs locally with `.venv/bin/python tests/pdf_sample.py`.
This writes `outputs/fixtures/native.pdf` and `outputs/fixtures/mixed-scan.pdf`.

### Neural and draft engines

XTTSv2 is the default selection, with built-in speaker `Ana Florence`:

```sh
.venv/bin/pip install -e '.[xtts]'
.venv/bin/pagevoice doctor
.venv/bin/pagevoice convert book.epub --device auto
```

XTTS needs a large first-use model download and operator acceptance of the
model's terms through Coqui's prompt. PageVoice never accepts them automatically.
Once cached, synthesis is local. CPU neural synthesis can be slow; benchmark a
chapter first. `doctor` probes CUDA/ROCm/MPS through PyTorch when installed;
without PyTorch, accelerator availability is reported as unverified.
GPU support is detected, not a guarantee of model/operator compatibility.
Use `--device cpu` if an MPS operation is unsupported.

Optional Edge draft synthesis sends book text to Microsoft and requires explicit
network opt-in; it is **not** an offline engine:

```sh
.venv/bin/pip install -e '.[edge]'
.venv/bin/pagevoice convert book.epub --engine edge --allow-network
```

Direct dependencies and optional engines are pinned in `pyproject.toml`.
The core transitive lock is recorded for Python 3.10.
`requirements-macos-py310.lock` additionally records the full installed optional
engine environment on this Mac; use `pip install -r requirements-macos-py310.lock`
inside the virtual environment to reproduce those versions. Other accelerator
platforms may need platform-specific PyTorch wheels. Voice cloning is not exposed
yet. Phase 4 will require a speaker-consent checkbox and notice before
accepting any reference sample.

### Local files

- `uploads/<session>.epub` (or `.pdf`): private source copy.
- `sessions/<session>/pages/*.json`: checksum-protected PDF page extraction/OCR cache.
- `sessions/<session>/session.json`: parsed book, settings, completed chunk records,
  status, errors, and output location; atomically replaced after each chunk.
- `sessions/<session>/chunks/*.wav`: persistent mono 24 kHz PCM speech chunks.
- `outputs/<session>.m4b` (or `.mp3`): assembled audio with metadata and chapters.
- `voices/`: reserved for later consent-based voice profiles.

All generated files and `.env` are excluded from Git. `.env.example` documents
shell configuration; `.env` is not loaded automatically. Unique session IDs avoid
output collisions; `resume` finishes failed or interrupted sessions using verified
completed chunks.

### Known limits at the phase 2 checkpoint

- One readable linear EPUB spine document per chapter; no NCX/nav fragment chapter
  splitting, cover art, footnote filtering, or DRM decryption. Headings are narrated.
- Only English and Spanish books are supported; very long
  sentences are subdivided to 220 characters. Engine language support varies.
- PDF reading order is best for simple, single-column books. Headers, footers,
  tables, and OCR mistakes may need manual sentence edits. Auto OCR uses a
  low-text threshold and can miss image text on pages with substantial native text;
  use `--ocr always` in that case. English OCR is tested; Spanish requires the `spa` Tesseract language data.
- API, web UI, cloning, speaker tagging, inline markup, and custom engines
  are pending their assigned phases. Recognized pause/voice markup is rejected
  instead of being narrated incorrectly.
- Per-sentence synthesis can produce audible prosody changes. No loudness mastering
  or speech-recognition quality check yet. PCM assembly temporarily uses disk space
  proportional to book duration (about 173 MB/hour).
- Real speech smoke tests use macOS `say`; other platforms skip those tests.
  XTTS and online Edge synthesis remain unverified; see the verification reports.
