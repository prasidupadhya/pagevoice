# PageVoice

A local-first PDF/EPUB → audiobook application, implemented from scratch.

## Development plan

Work stops for review after each phase:

1. EPUB → chaptered M4B CLI, engine registry, local smoke test.
2. PDF + OCR, crash recovery, sentence regeneration.
3. FastAPI upload, queue, progress (SSE), download.
4. React/Vite/Tailwind accessible reader UI, previews and consent-based voice cloning.
5. Character detection and voice casting.
6. Optional engines and an OpenAI-compatible speech endpoint.

`main` starts with this README only. Four feature branches cover the project:
`feat/pipeline` (1–2), `feat/api` (3), `feat/reader-ui` (4), and
`feat/voices-engines` (5–6). Maximum four commits per feature branch;
reviewed changes land through pull requests later. Do not create extra branches.

## Architecture

Parse → clean → chapters → sentences → optional speakers → audio chunks → FFmpeg.
Python CLI first, then FastAPI and React. Local `uploads/`, `voices/`,
`outputs/`, `sessions/`; no accounts. XTTSv2 via maintained `coqui-tts`
is the default engine; Edge is an optional online draft engine. Voice cloning
requires the speaker's consent. Model downloads require initial internet access.

## Implementation policy

Reference READMEs are inspiration only; no reference implementation is copied,
cloned, vendored, or wrapped. Standard PyPI/npm dependencies are allowed.
Design guidance will be read before phase 4. Every claimed working feature
must have a recorded verification run.

## Phase 1: CLI

On `feat/pipeline`, the core EPUB pipeline is implemented. The sample is original
text generated by `tests/sample.py`. Read [verification](docs/verification.md)
for tested paths and limitations; [reference notes](docs/references.md) record
README-only research.

### One-command setup

Prerequisites: Python 3.10–3.13 and FFmpeg/ffprobe on PATH. This machine was
verified with Python **3.10.12**, FFmpeg **8.1**, macOS arm64. Node **22.13.1**
is installed but not used until phase 4. On macOS, install FFmpeg with
`brew install ffmpeg` if missing, then run:

```sh
./scripts/setup.sh
```

The script creates `.venv` and installs pinned core/test dependencies using
`requirements-core.lock`. Override the Python executable with `PYTHON=python3.11`.
No model, cloud service, account, or API key is required for the macOS draft path.
Setup needs internet for PyPI; subsequent `say` conversions run offline with
an installed macOS voice.

```sh
.venv/bin/python tests/sample.py outputs/sample.epub
.venv/bin/pagevoice inspect outputs/sample.epub
.venv/bin/pagevoice convert outputs/sample.epub --engine say
.venv/bin/pytest -q
```

Use `--format mp3` for MP3; M4B is the default. `--voice Samantha` selects an
installed macOS voice (`say -v '?'` lists voices). `--language es` overrides EPUB
language. `--data-dir /path/to/library` sets the storage root. The CLI prints
the session and output paths. Book title, author, language, and chapter titles
are included in the output. MP3 chapter display depends on your player.

### Neural and draft engines

XTTSv2 is the default selection, with built-in speaker `Ana Florence`:

```sh
.venv/bin/pip install -e '.[xtts]'
.venv/bin/pagevoice doctor
.venv/bin/pagevoice convert book.epub --device auto
```

XTTS needs a large first-use model download and operator acceptance of the
model's terms through Coqui's prompt. PageVoice never accepts them automatically.
Once cached, synthesis is local. CPU neural synthesis can be slow; benchmark a
chapter first. `doctor` probes CUDA/ROCm/MPS through PyTorch when installed;
without PyTorch, accelerator availability is reported as unverified.
GPU support is detected, not a guarantee of model/operator compatibility.
Use `--device cpu` if an MPS operation is unsupported.

Optional Edge draft synthesis sends book text to Microsoft and requires explicit
network opt-in; it is **not** an offline engine:

```sh
.venv/bin/pip install -e '.[edge]'
.venv/bin/pagevoice convert book.epub --engine edge --allow-network
```

Direct dependencies and optional engines are pinned in `pyproject.toml`.
The core transitive lock is recorded for Python 3.10.
`requirements-macos-py310.lock` additionally records the full installed optional
engine environment on this Mac; use `pip install -r requirements-macos-py310.lock`
inside the virtual environment to reproduce those versions. Other accelerator
platforms may need platform-specific PyTorch wheels. Voice cloning is not exposed
in phase 1. Phase 4 will require a speaker-consent checkbox and notice before
accepting any reference sample.

### Local files

- `uploads/<session>.epub`: private source copy.
- `sessions/<session>/session.json`: parsed book, settings, completed chunk records,
  status, errors, and output location; atomically replaced after each chunk.
- `sessions/<session>/chunks/*.wav`: persistent mono 24 kHz PCM speech chunks.
- `outputs/<session>.m4b` (or `.mp3`): assembled audio with metadata and chapters.
- `voices/`: reserved for later consent-based voice profiles.

All generated files and `.env` are excluded from Git. `.env.example` documents
shell configuration; `.env` is not loaded automatically. Unique session IDs avoid
output collisions; failed conversion keeps completed chunks for future recovery.

### Known limits at the phase 1 checkpoint

- One readable linear EPUB spine document per chapter; no NCX/nav fragment chapter
  splitting, cover art, footnote filtering, or DRM decryption. Headings are narrated.
- Language-aware sentence splitting is limited to pySBD languages; very long
  sentences are subdivided to 220 characters. Engine language support varies.
- Resume and single-sentence regeneration are phase 2; rerunning currently creates
  a new session. Persistence alone is not a resume feature.
- PDF/OCR, API, web UI, cloning, speaker tagging, inline markup, and custom engines
  are pending their assigned phases. Recognized pause/voice markup is rejected
  instead of being narrated incorrectly.
- Per-sentence synthesis can produce audible prosody changes. No loudness mastering
  or speech-recognition quality check yet. PCM assembly temporarily uses disk space
  proportional to book duration (about 173 MB/hour).
- Real speech smoke tests use macOS `say`; other platforms skip those tests.
  Optional engine synthesis has separate verification status below.
